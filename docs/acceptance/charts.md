# Charts

Recharts' own examples (`tools/recharts/examples`, from recharts.org's `www/src/docs/exampleComponents`), drawn by
Pictor and compared with Recharts 2.15.4's render after mount in Chromium (`tools/recharts/out/<name>.client.html`,
Inter 14 px): element for element in document order, the same tags and classes, coordinates and path data within
0.01 px, the same colors, anchors, dashes, opacities and texts (`MarkupComparison`). What Recharts copies onto
elements without effect and its hidden tooltip are left out of the comparison. Pixel comparisons are in the demo page.

| Id | Criterion |
|---|---|
| CHARTS-01 | Given SimpleLineChart (a dashed grid, a category x-axis, a numeric y-axis, a tooltip, a legend and two monotone lines with dots), when Pictor writes it, then its markup matches Recharts': the plot shrinks by the legend's measured height (17 px), the y ticks are recharts-scale's 0 to 10000, the top tick label moves inside the chart, the legend is Recharts' HTML list. |
| CHARTS-02 | Given DashedLineChart, when Pictor writes it, then each line and each of its dots carry the line's dash array, as in Recharts. |
| CHARTS-03 | Given TinyLineChart (no axes, no margin prop), when Pictor writes it, then the line maps through hidden default axes over the whole chart less Recharts' default margin of 5, and no axis is drawn. |
| CHARTS-04 | Given BiaxialLineChart (a left y-axis and a right one with their ids), when Pictor writes it, then each line maps through its own axis, the right axis' ticks point right with labels anchored at their start, as in Recharts. |
| CHARTS-05 | Given LineChartWithReferenceLines, when Pictor writes it, then the vertical reference line sits at the "Page C" category and the horizontal one at 9800, each with its label centered on the line, as in Recharts. |
| CHARTS-06 | Given CustomizedLabelLineChart (a `LabelList` at the top of one line, `label` on the other), when Pictor writes it, then the labels sit 5 px above the points or centered on them with Recharts' anchors and color. |
| CHARTS-07 | Given SimpleAreaChart, when Pictor writes it, then the area runs from its monotone top line down to the baseline at 0 with a fill opacity of 0.6, and its stroke is a separate curve, as in Recharts. |
| CHARTS-08 | Given StackedAreaChart (three areas with one stack id), when Pictor writes it, then each area's baseline is the previous area's top and the y domain covers the sums. |
| CHARTS-09 | Given SimpleBarChart (two bar series), when Pictor writes it, then the bars share each band with a 10% category gap and a 4 px bar gap, their widths truncated to whole pixels, as Recharts' `getBarPosition` places them. |
| CHARTS-10 | Given StackedBarChart, when Pictor writes it, then the stacked bars share one slot and each starts where the previous ends. |
| CHARTS-11 | Given MixBarChart (two bars stacked and a third beside them), when Pictor writes it, then the stack takes one slot and the lone bar the next. |
| CHARTS-12 | Given PositiveAndNegativeBarChart (signed values, a reference line at y = 0), when Pictor writes it, then negative bars hang below zero (negative heights in Recharts' path) and the domain is recharts-scale's -10000 to 10000. |
| CHARTS-13 | Given BarChartWithCell (a `Cell` per bar, labels at the top), when Pictor writes it, then each bar takes its cell's fill and each label its bar's color, 5 px above the bar. |
| CHARTS-14 | Given BarChartHasBackground, when Pictor writes it, then each bar draws its band's background over the plot's height before the bars, in the background's fill. |
| CHARTS-15 | Given LineBarAreaComposedChart (an explicit band x-axis, an area, a bar, a line and a scatter), when Pictor writes it, then the series sit at band centers, the ticks and grid lines 2 px after each band's start (Recharts' offset for an explicit band scale), and the scatter's circles are d3's circle symbol of size 64. |
| CHARTS-16 | Given VerticalLineChart (`layout="vertical"`, a number x-axis, a category y-axis), when Pictor writes it, then the y categories run from the top down as points, each line goes through its values along x at the category's y, and the markup matches Recharts'. |
| CHARTS-17 | Given VerticalComposedChart (a vertical area, a bar of size 20 and a line on an explicit band y-axis), when Pictor writes it, then the area's baseline is the x of 0, the bars grow rightwards from it 20 px tall in the middle of their band, and the markup matches Recharts'. |
| CHARTS-18 | Given VerticalBarChart (SimpleBarChart with `layout="vertical"`), when Pictor writes it, then the two bars of each category share its band from the top down with Recharts' gaps and grow rightwards from the x of 0, and the markup matches Recharts'. |
| CHARTS-19 | Given ComposedChartWithErrorBars (an `ErrorBar` on a bar and one on a line), when Pictor writes it, then each bar has a whisker at its center and each line point one at its x, Recharts' `recharts-errorBars` layers where Recharts puts them, the y domain grows to cover the values plus their errors, and the markup matches Recharts'. |
| CHARTS-20 | Given LineChartWithReferenceAreas (an area between two categories with a label, a band between two values, a dot at the maximum with a label, a dot above the domain), when Pictor writes it, then the first area spans the plot's height between the categories' points, the band spans the plot's width, the dot sits at its value with its label centered, the dot outside the domain is discarded (`ifOverflow="discard"`, Recharts' default), and the markup matches Recharts'. |
| CHARTS-21 | Given VerticalBarChart whose bars set `activeBar` (fill pink and stroke blue, fill gold and stroke purple), when Pictor writes it for the web, then each category's hover state redraws that category's bars with those colors over the static ones, which keep their fills (the static markup is Recharts'). |
| CHARTS-22 | Given ComposedChartWithErrorBars, whose line sets `activeDot` to r 6, fill #ff7300, stroke #fff and stroke width 3, and LineChartWithReferenceAreas, whose second line sets `activeDot={false}`, when Pictor writes them for the web, then the first line's active dots carry those props and the second line has no active dot in any hover state. |
| CHARTS-23 | Given VerticalLineChart and VerticalBarChart with tooltips, when Pictor writes them for the web, then each has one hover state per y category: the line chart's cursor is a horizontal line across the plot at the category, the bar chart's cursor is the category's band across the plot, and each shared tooltip lists every series at the category (state 2: the label `Page C`, then `pv : 9800` in `#8884d8` and `uv : 2000` in `#82ca9d`, the series in order, as Recharts' shared tooltip) and sits 10 px right of where Recharts places a tooltip without a pointer (`combineCoordinateForDefaultIndex`: halfway between the plot's left edge and the chart's right edge) and 10 px below the category's coordinate (the line chart's tick, the bar chart's band middle) |
| CHARTS-24 | Given VerticalBarChart in a window, when the pointer moves over the third category's band 20 px right of the plot's left edge, then the chart's hovered category is 2 and its frame, against the frame before, draws the band cursor over the category where the bars leave it (more than 80% of the blank pixels of a column across the band painted `#ccc`), the tooltip box with its `#ccc` left border 10 px right of the pointer at the y the web writes for the state and more than 300 pixels of text inside it, and the active bars in their `activeBar` fills (`pink`, `gold`); when the pointer leaves the plot, then none is hovered and the frame is the frame before, pixel for pixel |
