# Clipping, references and range values

Recharts' clip paths (`allowDataOverflow` on an axis, `ifOverflow` on reference elements), the full `ReferenceLine`
(`segment`, `position`, the end points' order), and values given as `[low, high]` pairs (range areas, floating bars,
error pairs, a radar range) with `Area`'s `baseValue`. Each reference example is rendered by Recharts 2.15.4 itself
(`tools/recharts/catalog/ranges.mjs`); "matches Recharts" means the markup comparison of `samples/Demo/Reference`
finds no difference, which now includes the rectangle every `clip-path` refers to.

| Id | Criterion |
|---|---|
| CLIP-01 | Given DataOverflowComposedChart (a y-axis whose domain [0, 5000] cuts the data with `allowDataOverflow`, an area, bars, a line with error bars, a line with `dot clipDot=false`, a scatter), when Pictor writes it, then it matches Recharts': the domain is exactly [0, 5000], each series clips to Recharts' rectangle (the plot's height, twice its width centered on it): the area's inner layer, the bars' rectangles and their error bars, the line's curve, error bars and dots, the scatter's whole layer; the dots of the `clipDot=false` line clip to the plot grown by a dot (8 px). |
| CLIP-02 | Given DataOverflowScatterChart (an x domain [110, 170] that cuts the data, a joint line), when Pictor writes it, then it matches Recharts': the scatter clips to the plot's width and twice its height centered on it. |
| CLIP-03 | Given a chart without `allowDataOverflow` and without hidden references (SimpleLineChart), when Pictor writes it, then it writes no `clipPath` (Recharts writes one that nothing uses); and a clip's id names its rectangle, so two charts of one page never refer to each other's clips. |
| CLIP-04 | Given DataOverflowComposedChart built from its XAML elements, when the desktop control draws it, then nothing is drawn above the plot where the `pv` line leaves it, and the frame keeps the screenshot's size and fewer of its inked pixels than the example's limit (ORACLE-03) differ by more than 64 in a channel from Recharts' screenshot. |
| REFERENCE-01 | Given ReferenceOverflowLineChart (lines, areas and dots beyond the y domain with `ifOverflow` `visible`, `hidden` and the default `discard`), when Pictor writes it, then it matches Recharts': visible elements are drawn where they fall (an area's `radius` rounding its corners), hidden ones clip their line, rectangle or circle (not their label) to the plot, discarded ones are left out. |
| REFERENCE-02 | Given ReferenceSegmentBarChart (the x-axis on top, the y-axis on the right; lines at a category's band start and end, a line that extends the domain to 12000, a segment between two points, a segment beyond the domain, `isFront` on one line), when Pictor writes it, then it matches Recharts': the segment's points map through both axes at the band's middle, `position` moves a line to the band's start or end, the end points are ordered as Recharts orders them for a top x-axis and a right y-axis, the discarded segment is left out, and `isFront` changes nothing (Recharts 2.15.4 declares it and never reads it: references are drawn in declaration order). |
| REFERENCE-03 | Given ReferenceOverflowLineChart built from its XAML elements (`IfOverflow`, `ReferenceArea.Radius`), when the desktop control draws it, then the hidden line and area are clipped to the plot (no pixel of the hidden green line above the plot) while the visible ones are drawn above it, and the frame keeps the screenshot's size and fewer of its inked pixels than the example's limit (ORACLE-03) differ by more than 64 in a channel from Recharts' screenshot. |
| REFERENCE-04 | Given ReferenceSegmentBarChart built from its XAML elements (`ReferenceLine` with `X1`, `Y1`, `X2`, `Y2`, `Position` and `IfOverflow`), when Aioros asks the chart how it is written, then the markup written from its spec matches Recharts' render. |
| RANGE-01 | Given RangeAreaChart (a data key whose values are `[low, high]`, dots), when Pictor writes it, then it matches Recharts': the y domain covers both ends of every value, the area runs between the upper and the lower ends, its stroke is drawn along both edges, and the dots sit on the upper ends. |
| RANGE-02 | Given VerticalRangeAreaChart (the same ranges in a vertical layout with a monotone curve), when Pictor writes it, then it matches Recharts': the area runs between the lower and upper x at each category down the y-axis. |
| RANGE-03 | Given RangeBarChart (floating bars from `[low, high]`, labels at the top), when Pictor writes it, then it matches Recharts': each bar spans from its lower to its upper end and its label shows the upper end. |
| RANGE-04 | Given AreaBaseValueChart (areas with `baseValue` `dataMax` and 1000 and one inheriting the chart's `baseValue` `dataMin`), when Pictor writes it, then it matches Recharts': each area is filled to its own baseline, the area's own value taking precedence over the chart's. |
| RANGE-05 | Given ErrorBarPairsChart (errors given as `[low, high]` pairs, a plain value and a missing one, on a bar and a line), when Pictor writes it, then it matches Recharts': a pair's whisker runs from the value less its first end to the value plus its second, a missing error draws nothing, and the y domain covers every value plus and minus its errors. |
| RANGE-06 | Given RangeRadarChart (a radar whose values are `[low, high]`, dots), when Pictor writes it, then it matches Recharts': the radius domain covers both ends, the band between the upper and lower polygons is filled, and both edges are stroked, the lower one walked backwards as Recharts' in-place reversal leaves it. |

| RANGE-08 | Given range values held by C# members as an array, a `List<double>` and a `(double, double)` tuple, and a series' own items carried in its spec's table, when Pictor writes RangeAreaChart's spec over them, then each is read as Recharts reads an array (the table writes a pair as JavaScript writes an array, `-1,10`, and reads it back), and the markup equals the one written from Recharts' own data. |
| RANGE-09 | Given AreaBaseValueChart and RangeAreaChart built from their XAML elements (`Area.BaseValue`, `AreaChart.BaseValue`), when Aioros asks the charts how they are written, then the markup written from their specs matches Recharts' render. |

| RANGE-12 | Given StackedOwnDataAreaChart (a stack whose second area carries its own items), when Pictor writes it, then it matches Recharts': the stack is computed over the chart's items, the x-axis reads its categories from the series' own items, and each area takes its points from the stack by index; own items beyond the chart's leave their points out (Recharts fails on them). |
| RANGE-13 | Given a compiled page's chart writer over RangeAreaChart's data, when the same ranges come again, then the kept markup is written without laying the chart out; when only one lower end changes, then the chart is laid out again and the new markup differs (the writer compares the lower ends it read too). |
