# Data binding

How a chart follows its data on the desktop as an Avalonia `ItemsControl` follows its items: the bound value being
replaced, the bound collection's changes (`INotifyCollectionChanged`) and, below, a change of a property of an item
already in the data (`INotifyPropertyChanged`), for every chart family and for series, pies and funnels with their own
data. The subscriptions live while the chart is in the visual tree; the web writer subscribes to nothing, since each
request renders the current items.

| Id | Criterion |
|---|---|
| BINDING-01 | Given a chart of each family in a window, bound to items that notify their property changes (a line chart's point, a pie's own item, a funnel's own item, a treemap's nested leaf, a Sankey's link, a sunburst's nested node), when one item's property changes, then the chart is laid out again at its next frame and its layout holds the new value. |
| BINDING-02 | Given a line chart in a window over 100 items that notify their changes, when every item changes twice before the next frame, then no change lays the chart out by itself and the next frame lays it out once (one layout for 200 changes, coalesced by Avalonia's render loop), without replaying its enter animation (Recharts' update animation is not ported; a property change is not new data). |
| BINDING-03 | Given a chart in a window bound to an observable collection of items that notify their changes, when an item is removed (the chart laid out again for the removal) and the removed item then changes, then the chart is not laid out again and the removed item holds no handler; the same for an item replaced in the collection. |
| BINDING-04 | Given a chart in a window whose `Data` is replaced by another list, when an item of the old list changes, then the chart is not laid out again and the old items hold no handler, while a change of an item of the new list lays it out again. |
| BINDING-05 | Given a chart in a window following its data collection, its items, a nested list it reads (an observable list of a treemap node's children) and a series' own observable items, when it is removed from the window, then none of them holds a handler of the chart; when it is put back, it follows them again and is laid out with their current values (changed while it was out of the tree). |
| BINDING-06 | Given a chart in a window, when an item raises its property change on another thread, then the chart is not touched on that thread: the change is posted to Avalonia's dispatcher once however many changes arrive before it runs, and the chart is laid out again on the UI thread with the new value. |
| BINDING-07 | Given items that notify their changes, when the web writer writes a chart of them, then it attaches no handler to any item and writes their current values (the next request renders the changed items). |
| BINDING-08 | Given a line chart whose line's `StrokeWidth` (a number), `Dot` (a boolean), `Type` (an enumeration) and `Name` (a text), its y axis' `TickCount` (a whole number) and its x axis' `Hide` (a boolean) are bound to a model, when Aioros asks the chart how it is written, then each is declared as a part the plan reads, and the renderer given new values for all six writes byte for byte the chart Pictor writes from the spec of the chart bound to a model holding them; a bound property no hole can hold (a gradient stop's color, which renames its gradient) leaves the page to Aioros's engine (WEB-08), which renders the chart from its current values, so every bound property is followed on the web, and on the desktop by Avalonia's bindings (DESKTOP-04, BINDING-01..06). |
| BINDING-09 | Given a bar chart whose bars' `Fill` are bound to a model's Avalonia `Color`, to an `IBrush` holding a translucent solid brush and to an `IBrush` holding a linear gradient brush, and a fourth bar whose `SolidColorBrush` has its `Color` bound, when Aioros asks the chart how it is written, then each is declared as a part the plan reads with a paint hole, the chart is written by `BoundChartRenderer` (Pictor.Avalonia's renderer, which reads Avalonia's colors and brushes), and given new values (another color, the solid brush replaced by a gradient and the gradient by a solid brush, another color in the brush) the renderer writes byte for byte the chart Pictor writes from the spec of the chart bound to a model holding them: a color as `#rrggbb` (`#rrggbbaa` when translucent), a gradient as Pictor's gradient (`url(#pictor-gradient-…)` and its definition), a gradient no paint names any more left out of the definitions (a bound gradient stop's color is refused, WEB-08). |
| BINDING-10 | Given a line chart with a brush whose `Padding`, x axis' `Padding` and brush's `Padding` are bound to a model's `Thickness` values, when Aioros asks the chart how it is written, then each is declared as one part the plan reads with a hole per side the spec copies (the chart's and the brush's four sides, the x axis' left and right), and the renderer given new thicknesses writes byte for byte the chart Pictor writes from the spec of the chart bound to a model holding them. |
| BINDING-11 | Given a bar chart whose bar's `Radius` is bound to an Avalonia `CornerRadius`, its `BackgroundRadius` to a list of numbers and a reference area's `Radius` to a text, when Aioros asks the chart how it is written, then each is declared as a part the plan reads with a number list hole, and the renderer given new values (another corner radius, list and text) writes byte for byte the chart Pictor writes from the spec of the chart bound to a model holding them; on the desktop a corner radius rounds the bar's corners as Recharts' `[topLeft, topRight, bottomRight, bottomLeft]` (the order Avalonia's `CornerRadius` keeps), a number as all four, a list or a text as Recharts' array. |
| BINDING-12 | Given a line chart whose line's `StrokeDashArray` is bound to a list of numbers (Avalonia's `AvaloniaList<double>`, as `Shape.StrokeDashArray` takes) and its grid's to a text, when Aioros asks the chart how it is written, then each is declared as a part the plan reads with a dash hole, and the renderer given new values (another list, a text for the line and a list for the grid) writes byte for byte the chart Pictor writes from the spec of the chart bound to a model holding them; a list is written as Recharts' `strokeDasharray` text (`5 3`). |
