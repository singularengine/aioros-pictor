# The Gallery's live dashboard

The Gallery's home page (`/`) is a real-time analytics dashboard for three dummy products (Nimbus, a SaaS web app;
Pulse, a mobile app; Relay, a payments API), drawn with Pictor's charts on both targets. Its numbers come from a seeded
generator that is a pure function of the seed, the product and the time; a hosted ticker moves the dashboard's moment
once a second and invalidates the live key, so only the dashboard's live views (the live tile, the main chart, the event
feed) are rendered again and pushed. The product, the range and the focused page live in the URL
(`/?app=api&range=7d&focus=2`), so both targets share them.

The tests start the Gallery on a clock that stands still (`GALLERY_CLOCK`, two seconds before midnight, so the live
views cross a day) and tick it themselves (`POST /test/tick`, served only on that clock, runs one tick of both tickers
and answers once its keys are invalidated): a test awaits the push that follows its tick, never a second of real time.

| DASHBOARD-01 | Given the Gallery, when it is built with `build --precompile`, then every page (the landing page at `/{lang}`, the dashboard at `/dashboard`, `/about`, every chart family and feature page, the not-found and error pages) compiles to a plan in both themes and in each of the landing page's four cultures, the run reports as many precompiled pages as pages, and every page and theme writes the same bytes with generated accessors and with runtime delegates. |
| DASHBOARD-02 | Given the dashboard's number formats, when values are written, then counts are compact (842, 12.4k, 1.24M, 1.27B, rounding 999,999 to 1M), money has separators below $100k and is compact above ($3,210, $124k), percentages keep one decimal (2.3%) and two below 1% (0.42%), latencies are whole milliseconds (184 ms), and a value axis whose values reach 2,000,000 or more writes millions as `30M`, one reaching 2,000 writes thousands as `1.5k`, while a smaller one writes whole numbers with separators and a zero without a sign. |
| DASHBOARD-03 | Given a change against the previous period, when a delta is written, then it carries an arrow and a sign (`▲ +12.4%`, `▼ −3.1%`, `● 0.0%` when it rounds to nothing), so the direction never rests on color alone; and given a product's KPI tiles, then a tile's change is good when it goes the way its metric wants (more users, more revenue) and bad otherwise (an API's p95 latency or error rate going up is bad), and neither when it rounds to nothing. |
| DASHBOARD-04 | Given two generators with the same seed, when they compute a product's dashboard, KPI tiles, main chart and feed for the same moment, then the results are equal; a generator with another seed gives different traffic; and a bucket of a longer range keeps its value from one tick to the next while the Live range's last bucket follows the second. |

| DASHBOARD-06 | Given the top pages chart, when the bar at index 1 is clicked, then the page's command goes to the dashboard's address with `focus=1` and the same product and range; clicking the focused bar again goes to the address without the focus; an index off the list goes nowhere; and the main chart focused on that page is titled with the page's name and plots that page's share of the traffic, below the product's whole traffic in every bucket. |
| DASHBOARD-07 | Given the running Gallery and a client following the dashboard's live stream for Relay in the Live range, when the test ticks the Gallery's clock four times, reading the event after each tick, then each event is a `views` event carrying the regions of the three views that read it (the live tile, the main chart and the feed) and nothing of the rest of the page; the period's tiles, which read the history key, come only with a new minute (in the same event or one of their own); later events carry later update times, counted across midnight (the last at most an hour after the first, modulo a day); and over the 7-day range an event carries only the live tile and the feed, the main chart and the period's tiles (both reading the history key) coming only with a new minute. |
| DASHBOARD-08 | Given the dashboard's feed and its ticker, when a tick comes, then the feed's moment is replaced whole by the moment of the new second, the live key is invalidated, and the history key is invalidated only when the minute changes. |
