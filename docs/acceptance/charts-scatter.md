# Scatter charts

Recharts' `ScatterChart` examples (`tools/recharts/catalog/scatter.mjs`, from recharts.org's 2.x
`src/docs/exampleComponents/ScatterChart`), drawn by Pictor and compared with Recharts 2.15.4's render after mount in
Chromium, as the cartesian examples are (`MarkupComparison`: element for element, geometry within 0.01 px).

| Id | Criterion |
|---|---|
| SCATTER-01 | Given SimpleScatterChart (number x and y axes with data keys, names and units, a scatter with its own items), when Pictor writes it, then its markup matches Recharts': the x domain is recharts-scale's 0 to 180 with "cm" after each tick, each point is d3's circle of area 64 at its x and y. |
| SCATTER-02 | Given ThreeDimScatterChart (a z-axis with a data key and the range 60 to 400, star and triangle symbols, a legend), when Pictor writes it, then each symbol's area is the z-axis' linear scale from 0 to the largest z onto the range, the legend shows both scatters with circle icons, and the markup matches Recharts'. |
| SCATTER-03 | Given JointLineScatterChart (`line` on both scatters, cross and diamond symbols, a z-axis with the range [100] and no data key), when Pictor writes it, then each scatter joins its points with a linear curve stroked in its fill, every symbol has the area 100, and the markup matches Recharts'. |
| SCATTER-04 | Given ScatterChartWithLabels (a `LabelList` of the x values), when Pictor writes it, then each point carries its x value centered on it, as in Recharts. |
| SCATTER-05 | Given ScatterChartWithErrorBars (y error bars 4 px wide, x error bars 0 px wide, a reference area from 150 to 180 and 200 to 300), when Pictor writes it, then each point has its vertical and horizontal whiskers, the y domain covers every point plus its largest error (Recharts counts every error bar of a horizontal chart against its y-axis) while the x domain does not grow, the area is drawn in Recharts' default fill with its stroke, and the markup matches Recharts'. |
| SCATTER-06 | Given ThreeDimScatterChart with a tooltip, when Pictor writes it for the web, then it has one hover state per point (12): a transparent hit shape that is the point's symbol, a cross cursor through the point over the plot dashed "3 3" (written in the point's tip group, shown by the shared sibling rule, so the chart writes no rule per point: one `:has(` for five series of 1,000 points instead of 5,002), and Recharts' default tooltip listing "stature : 100cm", "weight : 200kg" and "score : 200km" for the first point; a point whose x is missing gets no hover state. |
| SCATTER-07 | Given ThreeDimScatterChart in a window, when the pointer moves over the third point of the first scatter, then the chart's hovered item is 2 and it draws that point's cursor and tooltip; when the pointer moves to an empty part of the plot, then no item is hovered. |
| SCATTER-08 | Given ThreeDimScatterChart built from its XAML elements (each scatter holding its own items), when the desktop control draws it (Avalonia, Skia, Inter at 14 px, device scale 1), then the frame keeps the screenshot's size and fewer of its inked pixels than the example's limit (ORACLE-03) differ by more than 64 in a channel from Recharts' screenshot in Chromium (most of this chart's ink is text, whose antialiasing differs between Skia and Chromium; the symbols themselves match). |
| SCATTER-09 | Given ThreeDimScatterChart built from its XAML elements, when Aioros asks the chart how it is written, then each scatter's spec carries its items as a table of the keys the chart reads (x, y and z), and the markup written from that spec matches Recharts' render. |
| SCATTER-10 | Given FittingLineScatterChart (one scatter with `lineType` fitting and line props stroke red, width 2, dashed "5 5"; one with a joint monotoneX line of width 3), when Pictor writes it, then it matches Recharts': the fitting line runs from the smallest to the largest x along Recharts' least-squares line, each line takes its props over the scatter's fill. |
| SCATTER-11 | Given points with a missing coordinate, or all at one x, when Pictor fits their line, then a missing coordinate counts as 0 (JavaScript's `cx \|\| 0`) and points at one x give a slope of 0 through their mean y, as Recharts' `getLinearRegression`. |
| SCATTER-12 | Given FittingLineScatterChart built from its XAML elements (`Scatter` with `Line`, `LineType`, `LineStroke`, `LineStrokeWidth`, `LineStrokeDashArray`), when Aioros asks the chart how it is written, then the markup written from its spec matches Recharts' render. |
