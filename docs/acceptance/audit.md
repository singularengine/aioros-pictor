# Audit fixes

The defects the code audit of 2026-10-15 found (`artifacts/audit/code.md`), each fixed with the behavior it now has.

| Id | Criterion |
|---|---|
| AUDIT-01 | Given a chart whose class names (the chart's, a series', an axis', the grid's, the tooltip's wrapper and label classes) hold `ok x" onmouseover="alert(1)` and the reserved `pictor-hits`, when it is written for the web, then every class attribute keeps `ok`, no attribute is opened by a class (`onmouseover` appears nowhere), the reserved token is left out (as many `pictor-hits` as without the class names), and a class name of safe tokens is written as it is. |
| AUDIT-02 | Given items whose own colors are `red;position:fixed;inset:0`, `url(https://evil.example/x)` and `expression(alert(1))` beside `#82ca9d` and `rgba(1, 2, 3, 0.5)` (a radial bar chart's, a pie's and a funnel's `FillKey`), and a tooltip cursor whose stroke and dash hold a declaration, when the chart is written for the web, then no refused value reaches the markup (no `position:fixed`, no `evil.example`, no `expression`), the valid colors are written, an item whose color is refused is drawn with the default color, and a style attribute only ever holds colors of the grammar (hex, `rgb()`/`rgba()`/`hsl()`/`hsla()` of numbers, a named color, `url(#id)`, `var(--name)`). |
| AUDIT-03 | Given a chart in a window following an observable collection, when an item is added to the collection on another thread, then the chart is not touched on that thread (no exception, no layout before the dispatcher runs): the change is posted to Avalonia's dispatcher once and the chart is laid out again on the UI thread with the new item. |
| AUDIT-04 | Given a chart in a window following an item, when the item is replaced by itself, moved to its own place, or removed and inserted again before the next frame, then the item holds exactly one handler of the chart and a later property change of it lays the chart out with the new value. |
| AUDIT-05 | Given a chart with a series, a bar with a cell and a brush with a panorama, when the series is removed from the chart (also after being added back once), the cell from the bar, or the panorama replaced, then a later change of the series, the cell or the old panorama's elements no longer lays the chart out, while a change of an element still held does. |
| AUDIT-06 | Given a brush's slide posted with the item count (10) and the start it was written at, when the renderer decodes it from the indexes' current values, then an unset end is the last item (start 2 and no end, posted start 1: 1 to 8), a start past the last that keeps the span stops at the edge with the span kept (window 2 to 5, posted 9: 6 to 9), the largest start the base holds does not overflow (6 to 9), indexes outside the data or reversed are clamped and ordered before the span is taken (8 to 100 posted 3: 3 to 4; 5 to 2 posted 0: 0 to 3), a slide posted at the start it was written at is refused (the framework posts every field and the post moved a traveller, so a stale slide never re-anchors the window), and a post without a count, negative, not a whole number or under another key is refused. |
| AUDIT-07 | Given a brush over 11 items with a `Gap` of 3 written for the web, when its range inputs are written, then the start input steps by 3 from 0 and the end input, whose last item 10 is not a step of 3, is written without a step so the browser can post the last item (Recharts keeps the end at the last item); with 10 items (a last of 9) both step by 3 (a brush with a gap writes its travellers as composite fields, AUDIT-45, whose indexes count from the value their range starts at). |
| AUDIT-08 | Given a desktop brush narrower than a traveller, when a traveller is dragged, then the drag neither throws nor leaves the strip: the traveller stays at the strip's start. |
| AUDIT-09 | Given a line chart whose numeric x axes are padded with `gap` and `no-gap` and whose items all have the same x (0, so the domain has no spread), when it is laid out and written, then the padding is none (Recharts' `calculatedPadding \|\| 0`): every axis range is finite and no `NaN` reaches the markup. |
| AUDIT-10 | Given a Sankey with a tooltip whose links all have a value of 0 and one of whose nodes has no link, when it is written, then no `NaN` reaches the markup (no node or link without a place is drawn, its hit target covers nothing and its tip stands at the origin), and every link and node keeps its hover state (6 of them). |
| AUDIT-11 | Given a funnel whose values are all 0 and whose `Width` is not a number, when it is laid out and written, then its trapezoids have no width (standing at the funnel's middle), no `NaN` reaches the markup and nothing throws; a `Width` that is not a number is no width, the chart drawn as without it. |
| AUDIT-12 | Given a radial bar chart with a tooltip whose radial bars are all hidden, when it is laid out and written, then it has no hover state and writes no hover layer, instead of reading a bar that is not there. |
| AUDIT-13 | Given a radial bar chart over the categories a, a, b (values 1, 2, 3) whose radius axis drops duplicated categories, and a radar chart whose angle axis does the same, when they are written, then the tooltip of a reads 1 and the tooltip of b reads 3, the first item of each category (Recharts' `findEntryInArray`), not the item at the category's index. |
| AUDIT-14 | Given a bar chart with two bars written alike (`DataKey="uv"`, one stack) and legend toggles, when it is laid out and written, then the second bar stacks on the first (its tops twice the first's) and each bar keeps its own toggle class (`pictor-s1`, `pictor-t1`); given the two bars without a stack, each takes its own slot of the band, the second to the right of the first (Recharts' `findPositionOfBar` finds a bar's position by its element): series are found by reference, not by value. |
| AUDIT-15 | Given a y axis whose `TickCount` is 0, when the chart is laid out, then it asks for no nice ticks (Recharts' `tickCount &&`): its domain stays the data's (9800) and it shows no tick; recharts-scale's ticks of an infinite domain with a count of 0 are the finite bound alone, without failing. |
| AUDIT-16 | Given a domain bound `dataMin - NaN`, `dataMin - -5`, `dataMin - 1e3` or `dataMax + 2.`, when it is read, then it is not a shift (the data's bound stays), as Recharts' `MIN_VALUE_REG`/`MAX_VALUE_REG` accept unsigned decimals only; `dataMin - 5` and `dataMax + 1.5` still shift. |
| AUDIT-17 | Given a stacked bar chart with the wiggle offset under a brush from 2 to 5, when it is laid out, then the bars' stacks are taken over the whole data and the window shows their points 2 to 5 (the tops equal the whole chart's at those points), as Recharts stacks its whole data before slicing. |
| AUDIT-18 | Given an axis whose `TickFormat`, a tooltip whose `LabelFormat` and a legend whose `Format` are `{1}`, `{`, `}` or `{0:X}` (a specifier a double refuses), when the chart is written, then nothing throws and every text is written as it is without a format, as Recharts writes a value without a formatter (the markup equals the chart's without the formats); `{0:N0}`, `{0,8}` and `{{{0}}}` still format. |
| AUDIT-19 | Given a compiled page's treemap that kept its markup for items with only a capitalized `Name`, when a request's items also carry `name` (which a fresh render reads), then the kept markup is not served: the markup equals a fresh render's and shows the `name` texts (each key's resolution, `name` or `Name`, is part of what a kept render compares). |
| AUDIT-20 | Given the sync ids `ab`, `a.b`, `a_b`, `a__b`, `a_2e_b`, `売上`, `利益`, `a b` and `a-b`, when their classes are written, then no two are the same, each is a class of letters, digits, dashes and underscores, and an id of letters, digits and dashes keeps its class (`pictor-y-ab`, `pictor-y-a-b`). |
| AUDIT-21 | Given items whose value is a boolean, when the key is read as texts, then it is `true` or `false`, as JavaScript's `String(b)` writes it. |
| AUDIT-22 | Given a bar shape template whose rectangle's `Fill` is bound to `Payload[color]`, when the chart's spec is built, then the template is refused with its reason (`the Fill of the template's Rectangle is bound and gives no brush`), instead of compiling to a constant `fill="none"` for every item. |
| AUDIT-23 | Given a bar shape template drawing a `Border` with `Background="#80000000"` and a tooltip template whose border has that background and whose text is `#80ff0000`, when they are written for the web and drawn on the desktop, then the web writes `fill="rgba(0,0,0,0.502)"`, `background:rgba(0,0,0,0.502)` and `color:rgba(255,0,0,0.502)`, and the desktop draws the bar half dark over white (a gray between 110 and 145), not opaque black. |
| AUDIT-24 | Given `Calc` expressions with a signed exponent (`Height*1e-3 + Height`, `2.5E+1 - 2.5e-1`) (only ASCII digits start a number), when they are read, then the exponents are numbers: they load and the template compiles instead of failing at `1e`. |
| AUDIT-25 | Given a treemap node template shown at depth 1 and above depth 100 (two ranges of a whole number) and a bar shape template shown while `Value > 1e-7`, when they are compiled, then the first is refused (`is not one condition on its members`) instead of compiling to one half-line, and the second keeps its threshold (a constant of -1e-7, exclusive) instead of rounding it to 0. |
| AUDIT-26 | Given a window with Pictor's theme whose resources redefine `PictorPalette` as three colors, when `PictorPalette2` and `PictorPalette4` are looked up from a control in it, then the second is the redefined palette's second color and the fourth is not found; without the redefinition the second is Pictor's palette's. |
| AUDIT-28 | Given a line whose bound `StrokeWidth` (10) the spec clamps to at most 10, and another line whose bound `StrokeWidth` the spec copies, when the chart's bound parts are found, then the clamped one is not declared (the far marker leaves the spec unchanged, an ordinary value changes it, so the plan refuses it by name rather than writing it frozen) and the copied one is declared with its hole. |
| AUDIT-29 | Given a chart whose line's `StrokeWidth` has a data binding, another line's a multi binding and an axis' `TickCount` an observable bound by code (as a resource is), when its bound parts are found through Avalonia's public API, then only the data binding is declared. |
| AUDIT-27 | Given a responsive bar chart with item tooltips laid out at 60 and 1200 px over 400 items (fewer bars are drawn at 60 px, so it has fewer hover states than at 1200 px), when it is written, then the hover rules are written for the layout with more states, not only for the first width. |
| AUDIT-30 | Given FunnelChart with legend toggles, when it is written for the web, then each of its five tips is a hover state's group (`pictor-tkK`, hidden at rest by the shared rule and shown by its hit group) holding the toggle's group (`pictor-s0`) inside it, not the toggle's group in the state's place (which no rule hid, so every tip showed at rest); checked in Chromium and Firefox on the Gallery's `/families`: no tip at rest, one on hover, none after leaving. |
| AUDIT-31 | Given NestedTreemap zoomed into `axis` with its zoom buttons, when it is written for the web, then the trail's boxes off the zoom are not written at all (they were written hidden, and their `hidden` attribute lost to the inline `display:inline-block`), the boxes written are shown (`display:inline-block`) and read `root` then `axis`; the Gallery's nest treemaps name their nodes (`NameKey="Name"`, as Recharts' NestedTreemap example's `nameKey`). |
| AUDIT-32 | Given Pictor's themes, when a polar radius axis' tick labels are drawn, then they take their own color (`PictorPolarTickText`): Recharts' `#ccc` in the light theme, and in the dark theme a gray of at least 4.5:1 (WCAG AA) against black and the Gallery's `#09090b`, while the axis line keeps its faint `#313131`. |
| AUDIT-33 | Given BrushWindowBarChart with the keyboard layer and its brush's fields, when it is written for the web, then the brush's range inputs are the surface's last children, after the categories' hit groups (the first tab stop is the categories, as Recharts' surface comes before its brush), and the rules drawing a dragged traveller find them from the surface. |
| AUDIT-34 | Given Sankeys over 40 random node sets (acyclic, and a quarter with cycles) and one of 30 layers of 4 nodes each linked to every node of the next (4^29 paths), when they are laid out, then every node's depth is the one Recharts' recursion gives (each target one deeper than its deepest source, the nodes without targets in the last column), the layered graph's depths are its layers, computed once per link in topological order instead of once per path. |
| AUDIT-35 | Given a pie whose own data (2,000 items) is a bound table hole, when the chart is rendered again for the same items, then the items are compared with the kept table on the live items (no new table is read): the spec is filled once, the third render writes the same markup allocating no more than its copy into the test's buffer and string (8 bytes per character, plus 16 KB) where reading the table costs far more, and changing one item's value in place fills the spec again.
