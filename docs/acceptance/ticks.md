# Ticks

recharts-scale's tick values (`getNiceTickValues`, `getTickValuesFixedDomain`), checked against recharts-scale 0.4.5
itself (`tools/golden/ticks.mjs` writes `tests/Aioros.Pictor.Tests/Golden/ticks.json`), and the ticks an axis shows and
how it draws them, checked on reference examples rendered by Recharts (`tools/recharts/catalog/axes.mjs`) with the
comparison of [charts.md](charts.md).

| Id | Criterion |
|---|---|
| TICKS-01 | Given a domain, a tick count and whether decimals are allowed, when the nice ticks of a numeric axis with an automatic domain are computed, then they equal recharts-scale's `getNiceTickValues` for the same inputs, value for value, over 268 cases (ascending, descending, negative, fractional, single-valued and zero domains). |
| TICKS-02 | Given a fixed domain, when its ticks are computed, then they equal recharts-scale's `getTickValuesFixedDomain`, value for value. |
| TICKS-03 | Given a domain that crosses zero with a tick count of 2, for which recharts-scale recurses until the stack overflows, when the nice ticks are computed, then the port stops after 64 step corrections and returns no ticks instead of failing. |
| TICKS-04 | Given RotatedTickBarChart (twelve month names on an XAxis with `angle=-45`, `textAnchor="end"` and a height of 70) and SteepTickLineChart (the same names at -90° on the bottom axis and at 30° with `textAnchor="start"` on a top axis), when Pictor writes them, then their markup matches Recharts': each tick label is rotated by `rotate(angle, x, y)` around its point with the given anchor, and the labels kept are those whose rotated boxes do not collide (Recharts' `getAngledTickWidth`: the widest horizontal line inside the rotated box, the label's line height when steep). |
| TICKS-05 | Given StyledAxesChart (an XAxis with `tick={{fill, fontSize: 12}}`, `axisLine={{stroke, strokeWidth: 2}}`, `tickLine={{stroke}}`, `tickSize` 10 and `tickMargin` 6, and a YAxis with `tick={{fontSize: 10, fill}}`, no axis line and a 3 px tick line), when Pictor writes it, then its markup matches Recharts': the tick labels carry the tick props' fill and `font-size`, the lines their own stroke and width, collisions are measured at the ticks' font size, and the grid's lines at the chart's. |
| TICKS-06 | Given AxisOptionsChart (an XAxis on top with padding 30 at both ends and `minTickGap` 20, and a YAxis on the right, mirrored, reversed, with unit `kg`, 8 ticks and no decimals), when Pictor writes it, then its markup matches Recharts'. |
| TICKS-07 | Given ExplicitTicksChart (a numeric XAxis with domain `[0, 100]` and `ticks` 0, 25, 50, 75, 100, and a YAxis with `ticks` 0 to 120 by 30 over data up to 96), when Pictor writes it, then the axes show exactly the listed ticks, and the y domain widens to 120 to hold them (the end of Recharts' `detectReferenceElementsDomain`), as in Recharts. |
| TICKS-08 | Given EquidistantTicksChart (forty categories on an XAxis with `interval="equidistantPreserveStart"` and on a top XAxis with `preserveStartEnd`), when Pictor writes it, then the first axis shows the first tick and every n-th after it with the smallest n whose labels do not collide (Recharts' `getEquidistantTicks`), and its markup matches Recharts'. |
| TICKS-09 | Given WrappedTicksChart (category names such as "North America", wider than the 60 px YAxis of a vertical bar chart) and VerticalTimeChart (a date label wider than its XAxis' width), when Pictor writes them, then each tick label wider than its axis' width is broken at its spaces into lines that fit it (Recharts' `Text` with the axis' `width`: a word joins a line while the line, the word and a no-break space stay narrower), written as one `tspan` per line, the first shifted by its vertical anchor (`-0.145em` for two lines in the middle) and the next by `1em`, and the markup matches Recharts'. |
| TICKS-10 | Given SimpleBarChart's data with each category a date, as an ISO text (`2024-04-01`, shadcn/ui's interactive charts) and as a `DateTime` (its months), an x-axis `TickFormat` of `{0:MMM d}` and a tooltip `LabelFormat` of `{0:MMMM}`, when the web writes the chart, then each tick reads its date formatted (`Apr 1`, `Apr 2`...) and each hover state's label the month (`April`), as shadcn/ui's `tickFormatter` and `labelFormatter` format `new Date(value)`; the categories of SimpleBarChart's own data (`Page A`), which read as no date, keep their text under the same formats. |
| TICKS-11 | Given SimpleBarChart with an x-axis `TickFormat="{0:MMM}"` over dates, a tooltip `LabelFormat="{0:MMMM}"` and a y-axis `TickFormat="{0:N1}"`, when the same writer writes it under `en-US`, `es-MX` and `ja-JP`, then the composite formats follow the current culture (`Apr`, `abr`, `4月`, the tooltip's month name and the value's digits as that culture writes them, as a browser's `toLocaleString` does for Recharts' formatters and as a binding's `StringFormat` does on the same page) and the markup kept for one culture is never served to another; a value with no format stays as JavaScript writes it, whatever the culture. |
