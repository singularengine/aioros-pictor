# The Gallery as the demo

Pictor's demo is its Gallery (decided with the user on 2026-10-14): what the port does, on the web and the desktop,
each part reachable from the sidebar.

| Id | Criterion |
|---|---|
| GALLERY-01 | Given the running Gallery, when `/compare/{family}` is requested for each of the twelve families, then the page holds one card per reference example of that family (every example of `tools/recharts/examples` of its kind, in name order, those with custom content left to `/custom`), each with Recharts' screenshot (`/reference/<name>.png`, served as `image/png`), Pictor's chart written by Pictor's writer, the element verdict of the comparison the tests use (`Elements: all N match` or `Elements: D of N differ`) and the share of inked pixels that differ strongly as `samples/Demo/compare.mjs` recorded it in `Reference/pixels.json`; the family's page and the comparison's index (`/compare`, linked from the sidebar) link to it, and an unknown family answers 404. |
| GALLERY-02 | Given the running Gallery, when `/families` is requested, then it holds a chart of each of the twelve families with its tooltip's hover states (hover and touch), legend toggles where Recharts' family renders a legend (not the treemap, the Sankey or the sunburst), a brush's two range inputs on the line, area, bar and composed charts, Recharts' keyboard focus on the cartesian charts (the roving focus or a focusable surface) and none on the others, and item buttons: posting the first button of each family's chart answers the page with that family's command having run with the button's parameter; the page links the live charts and the sidebar's theme switch holds `/theme/system`; each card holds one legend checkbox per legend item; in Chromium, the mouse resting on a point of each card's chart that the browser hit-tests to a hover state (a hit shape or a state's button) shows exactly one tooltip box in that card and none before (a funnel's tips toggled by its legend kept in their states' groups, so they stay hidden until hovered). |
| GALLERY-03 | Given the running Gallery in Chromium at 390 px and at 1024 px wide, when each sidebar route and each `/compare/{family}` is loaded, then the page never scrolls sideways (the document's scroll width equals the viewport's), no element outside a chart's SVG reaches left of 0 or right of the viewport unless a horizontal scroll container holds it (a chart that keeps its pixel size, as the comparison panels do, scrolls inside its own box, starting at the box's left edge so that nothing is out of reach), and no two links' texts overlap; a page that overflows or overprints fails with its route, its width and the element. |
| GALLERY-04 | Given the Gallery's samples, when a page is rendered in the dark theme, then the neutral colors its charts set (the funnel's label list, bar and radial bar backgrounds, the tooltip cursor band, the grid's stripes, a brush's fill) are the dark values of the Gallery's sample keys (`#ededf0` labels, `#161616` backgrounds, `#1b1b1f` bands and stripes), and in the light theme the literals of Recharts' examples (`#000`, `#eee`, `#f5f5f5`, `#f4f4f4 #fff`); neither theme draws the other's value. |
| GALLERY-05 | Given `Reference/pixels.json` recording, per reference example, the share of inked pixels that differ strongly and the hash of the Pictor markup it was measured on (written by `samples/Gallery/pixels.mjs` from `compare.mjs`'s results), when `/compare/{family}` is requested, then an example whose markup Pictor still writes shows its share, one measured on another markup or never measured shows `Pixels: not measured…` and the pill `not measured`, the headline counts as matching only examples measured on the current markup (`M of N measured reference examples match…`, then how many were not measured), and the page states the Chromium version, the commit and the date of the measurement; a family of one measured match and one unmeasured example reads `1 of 1 measured … ; 1 not measured …`, never `2 of 2`. |
| GALLERY-06 | Given the running Gallery and a client following `/live-charts`'s live stream, when the ticker ticks, then each family's view reads a key of its own and is pushed only at the ticks it is due (every fourth second, a quarter of the families at a tick), so that over the pushes read (at least six, until every family came twice) a push carries on average at most half of the families and a family's view is pushed at most once per four ticks spanned (plus one), where every push carried every family before, and every morph a pushed view declares ends (its delay plus its duration) before the family's next push. |
| GALLERY-07 | Given the running Gallery, when `/en`, `/es`, `/zh` and `/ja` are requested, then each answers 200 with `<html lang>` set to its culture (`en`, `es`, `zh-Hans`, `ja`) and Pictor's landing page in that language (decided with the user on 2026-11-01: each library has a site of its own): its promise, its three measured figures (12 chart types, 96× Recharts' server render, Recharts 2.15.4) with the measurement they come from (docs/benchmarks.md, iteration 12), a live chart of each of the twelve families linking to its gallery page (`/line` … `/sunburst`), a link to the comparison with Recharts (`/compare`), the XAML to start with, and a link to Aioros's site; the gallery's pages keep no landing page of their own beside it, and the sidebar's layout is not around it. |
| GALLERY-08 | Given a request for `/`, when its `Accept-Language` prefers Japanese (`ja,en;q=0.5`), Spanish through a region (`es-MX`), a language the landing lacks (`fr`) or nothing, then it redirects to `/ja`, `/es`, `/en` and `/en`; and `/fr` answers 404. |
